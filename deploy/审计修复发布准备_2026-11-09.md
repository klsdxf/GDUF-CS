
## 3. 保存恢复点

在旧版本仍运行时执行，任何一步失败均停止。暂停业务写入后备份，可获得数据库和媒体的一致恢复点。若发布与回退跨终端进行，按实际路径重新设置变量。

```bash
cd /root/gduf-cs
umask 077
release_stamp="$(date -u +%Y%m%dT%H%M%SZ)"
release_backup="backups/pre-audit-$release_stamp"
bash scripts/backup.sh "$release_backup"
git rev-parse HEAD > "$release_backup/source-commit.txt"
git branch --show-current > "$release_backup/source-branch.txt"
docker compose images > "$release_backup/images.txt"
cp -p .env "$release_backup/environment"
tar -czf "$release_backup/edge-config.tar.gz" -C storage ip-edge
docker compose -f compose.yaml -f deploy/compose.ip.yaml exec -T edge nginx -T > "$release_backup/edge-expanded.conf" 2>&1
docker compose exec -T web nginx -T > "$release_backup/web-expanded.conf" 2>&1
docker image tag "$(docker compose images -q api)" "gduf-audit-api:before-$release_stamp"
docker image tag "$(docker compose images -q web)" "gduf-audit-web:before-$release_stamp"
printf '%s\n' "$release_stamp" > "$release_backup/release-stamp.txt"
```

保存 `release_backup` 的实际路径，复制受控异地备份，不提交 Git。证书需要变更时，还需按主交接文档单独备份证书卷；上述步骤没有备份私钥。

## 4. 获取已推送版本并固定提交

优先通过 Git 获取，不将压缩包解压覆盖正在运行的仓库。先用本次发布包外置 `release-manifest.json` 核对预期 SHA。

## 5. 构建并按顺序更新服务

以下交互要求维护者明确输入已核实的现用模式；不是默认选择 demo。

```bash
read -r -p '输入已核实的现用模式 demo 或 api: ' release_mode
case "$release_mode" in demo|api) ;; *) echo '模式无效，停止发布'; exit 1 ;; esac
export VITE_PUBLIC_DATA_MODE="$release_mode"
docker compose -f compose.yaml -f deploy/compose.ip.yaml build api web
docker compose -f compose.yaml -f deploy/compose.ip.yaml up -d --no-deps --wait api
docker compose -f compose.yaml -f deploy/compose.ip.yaml up -d --no-deps --wait web
docker compose exec -T web nginx -t
docker compose exec -T web nginx -s reload
docker compose -f compose.yaml -f deploy/compose.ip.yaml up -d --no-deps --wait edge
docker compose -f compose.yaml -f deploy/compose.ip.yaml exec -T edge nginx -t
docker compose -f compose.yaml -f deploy/compose.ip.yaml exec -T edge nginx -s reload
```

edge 此次需要重建容器配置以增加 snippets 挂载；仅 reload 不会新增挂载。服务更新后先验证现有 www 入口和后台。API 模式下后端检查不可用会使资源页返回服务错误，不能跳过 API 更新只更新静态前端。

## 6. 更新实际域名入口配置

仅修改模板不会改变 `storage/ip-edge/domain.conf`。先读取现用入口并确认实际域名、证书路径和额外 location；保留自定义配置。

若确认现用规范域名为 `www.gdufcs.fun`，现阶段只启用 www，且现用配置无额外自定义规则，可使用新域名脚本重新生成单域名配置：

```bash
bash scripts/domain-https.sh enable www.gdufcs.fun
```

该脚本会备份环境和入口配置，并可能重建 API；执行后再次确认上游健康。若现用配置已有裸域或其他域名，不得用单域名命令删除它们；按已核实的 SAN、DNS 和域名列表合并配置。只有双域名证书和 ACME 条件均满足后，才使用双域名 request/enable，具体见 11 号交接清单。

## 7. 验收与关闭

先检查 www，不因裸域尚未实施而跳过核心服务验收：

```bash
curl --fail --max-time 15 https://www.gdufcs.fun/api/v1/health
curl --fail --max-time 15 https://www.gdufcs.fun/ > /dev/null
curl --silent --show-error --max-time 15 -o /dev/null -w '%{http_code}\n' https://www.gdufcs.fun/audit-missing-path
curl --silent --show-error --max-time 15 -o /dev/null -w '%{http_code}\n' https://www.gdufcs.fun/matches/audit-missing-id
```

两个不存在路径必须是 404。API 模式另验未发布比赛、跨届队伍、未来公告、正常深链和后端不可用的 503；在隔离实例模拟故障，不主动停止生产 API。验证 HTML、静态资源、API 成功/失败和错误响应的安全头，确认压缩与 h2。

待裸域也已实施后运行完整公网检查：

```bash

```

保存 HTTP 原始输出、nginx -T、当次资源哈希、构建模式、镜像 digest 和浏览器截图。检查赛程、直播、积分队伍弹窗、后台登录、只读管理查询与媒体。真机、分享、字号放大及其他边界继续按 [修复交接清单](../开发文档/11_审计问题修复交接清单_2026-11-09.md) 补验，逐项关闭，不能仅用健康接口成功替代验收。
