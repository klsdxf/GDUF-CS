主要写入口映射：

| 入口 | 事务或锁行为 |
| --- | --- |
| 赛事、公告、直播、队伍和导入 | 路由委托服务，锁赛事并读取新状态，全局设默认赛事按 ID 加锁。直播、公告和队伍改动由 ORM 捕获缓存失效 |
| 阶段、赛程、成绩、晋级 | 锁赛事，对已确定参赛方绑定名单版本；成绩修正和晋级显式使正式发布失效，老入口有 ORM 保护 |
| 排名、赞助、奖品 | 赛事和结果页锁，发布按类别及主键锁来源；品牌修改使用版本 CAS；品牌或工作稿正常编辑保留已发布快照 |
| 示例导入、旧季赛更新、季军与奖品脚本 | 调用服务并共享外层事务，批量撤换记录明确标记公开缓存失效 |
| 登录、改密和初始化 | 会话和唯一管理员在 PostgreSQL，登录窗口在 Redis；会话失效和密码变更同事务 |
| 上传 | 先检查身份和数量限制，再解析文件；图片或工作簿处理移入线程，数据库与媒体以停写窗口协调备份 |

运行证据：

- 真实 PostgreSQL 后端回归 61 项通过。常规任务跳过专用 Redis 用例，另启动两个真实 API 进程执行 5 项 Redis/PostgreSQL 专项，全部通过。
- 通用 Playwright 回归通过 78 项，4 项按用例条件跳过。两条真实 API 流程通过，覆盖排名发布、撤回、重发，以及示例数据导入、关联和重新打开。Vue 类型检查、CSS 检查和生产构建通过。
- 测试数据库包含 31 届、7,321 场合成比赛和 14,796 条审计。公开赛程关闭缓存时，热点赛事 31 场从 98 次 SELECT 降到 5 次，243 场的历史赛事从 1,460 次降到 5 次。前后各执行三次。查询路径、数据集、耗时和 EXPLAIN 见 `reports/backend-quality-query.json`。样本使用现有赛事索引，热赛事的排序约 0.173 ms，暂未为简单时间排序额外增加联合索引。
- 本机单 API 进程、真实 PostgreSQL 和 Redis，直接经本机 HTTP 作两轮 20 秒短测。热缓存 2,000 请求，99.97 请求/秒，P95 36.92 ms，P99 44.27 ms。关闭缓存 400 请求，20.01 请求/秒，P95 48.40 ms，P99 65.96 ms。两轮非 200 均为 0。分接口结果见 `reports/backend-quality-smoke-hot.json` 与 `reports/backend-quality-smoke-uncached.json`。这是开发样本，正式负载需按 20 号方案经过 Nginx、独立负载机和指定资源窗口测量。
- 将含 104 个历史名单版本、1 个排名快照及 WebP 的 PostgreSQL 数据恢复到独立空库和空媒体目录。清单相同，数据库导入至清单校验约 2.2 秒。另在独立 Compose 项目用交付的停写备份和恢复脚本复验媒体、数据及清单，恢复和清单校验约 4.0 秒。生产备份频率、异地副本和真实 RPO/RTO 仍需演练记录。
- Windows 默认测试临时目录可复现创建失败。使用项目内短目录和超时堆栈配置后完成测试。隔离 Compose 首次登录另发现缺席的 edge 代理名导致 DNS 等待，现按基础部署和外层代理部署分别配置可信名称。Nginx 定期重新解析容器地址，独立 Compose 的健康、内部路径隔离、404、媒体及登录冒烟通过。
- 隔离 PostgreSQL 停机时，API 存活探针仍为 200，数据库就绪探针返回 503，且响应头与错误体中的请求 ID 一致。
- Compose 空闲样本中，API、失效 worker、Redis、PostgreSQL 和 Nginx 分别约占 83.6、60.5、10.1、24.9 和 14.6 MiB。此样本用于记录本地基础开销，峰值由正式稳态压测和 AOF 重写演练测定。
