# 前端设计精确还原规范

版本：V1.1｜2026-11-08｜唯一已选方案：**广金主场 · 观赛优先**。

## 1. 最高约束与资产

用户明确要求与已提供示意“一模一样”。不是“参考这个风格”，也不是重新做一个类似电竞站。必须先用相同示例数据还原指定首页，再绑定真实数据。不得混入双方案第二个“木棉赛刊”，也不得回到之前的 Campus、Arena、Matchday。

权威文件位于 `前端设计基准/`：

- `gduf-cs2-designs.original.fragment.html`：用户看过的双方案原始快照，完整保留。
- `广金主场_观赛优先_选定稿.fragment.html`：只保留所选第一个方案；原稿 CSS 和脚本不重新设计。
- `广金主场_观赛优先_预览.html`：可在浏览器打开的导出预览。
- `原稿样式基准.css`：原始 style 块的逐字提取，包含未选方案的规则；实现只移植 `.g-match` 所用规则及共享规则。
- `设计基准清单.json`：来源、方案名称、提取方式、SHA-256，防止后续误覆盖。

原始片段不依赖对话中的临时显示继续存在。开发不得修改基准文件去“匹配”错误的产品实现。

## 2. GDUF 身份与使用方式

页面品牌是“广金主场 ↗”，辅助标识为 `GDUF COUNTER-STRIKE 2`。顶部院校条写 `GDUF 广东金融学院` 和 `学生社团赛事 / CAMPUS CS2`，不伪称学校官方主办。

学校官方资料给出红色校徽、木棉意象、校训“明德、敏学、笃行、致远”。原稿把这些转为设计红、抽象木棉纹样、校训细节；没有把抽象图案当作真实校徽。设计红的十六进制值来自本次设计，不应标注为学校官方标准色。将来使用正式校徽须采用组织者提供的正确原图，不手工猜画。

来源：[广金标识](https://qyxq.gduf.edu.cn/xqgk/gjbs.htm)。结构参考：[HLTV 赛程](https://www.hltv.org/matches)、[BLAST CS](https://blast.tv/cs)。这些是研究来源，不代表允许把他站品牌、广告、账号系统或版面原样搬进产品。

## 3. 首页从上到下的固定结构

主标题保持 `广金主场。` 换行 `为这一局集结。`；第二行设计红、非斜体。引导文案是“从校园五排，到全场焦点。／属于广金玩家的每一轮，都值得被看见。”按钮“查看比赛日”。右图大字按 `GD`／`UF↗` 排列，辅以英文院校全称、`OUR CAMPUS. OUR GAME.` 和淡木棉纹样，不换成枪械图、泛用游戏角色或另一版海报。

## 6. 响应式必须与原稿一致

断点为 `max-width:760px` 和 `max-width:540px`，不是 UI 库默认断点。

760px 及以下：水平内边距改 22px；导航栏目换到下一行；赛季移到右侧；主视觉比例 1.4:1，标题 42px；右 GDUF 字 107px；比赛区比例 1.55:1、gap 20px；比分 44px；地图名和比分上下排列。

540px 及以下：

- 主视觉变单列；左文案在上、红色字形在下，右图最小高度 206px。
- GDUF 由两行变单行，104px；隐藏大字旁箭头，保留品牌身份；木棉纹理继续显示。
- 校训另起一行；比赛区变单列，焦点对决在前、积分榜在后。
- 焦点比分 48px；队标 57×63px；积分行上下 13px。
- 赛程行改两列 `42px 1fr`，元信息放第二列下一行；日期按钮最小高 44px。
- 所有内容正常纵向流动，不横向压缩整张桌面图、不隐藏积分榜、不靠截图缩放适配。

片段外层 `section[data-variant]` 的 1120／1700px 最小高度属于方案切换舞台，不能当生产页面固定高度。`.g-site` 的最小高度按原稿保留用于静态比对；真实内容增加后允许自然增长。

## 7. 组件与交互

建议 Vue 组件：`UniversityBar`、`PublicHeader`、`GdufMasthead`、`TournamentStrip`、`FeaturedMatch`、`MapScoreStrip`、`GroupStandings`、`MatchdaySchedule`、`PublicFooter`。组件拆分不能改变 DOM 布局和样式优先级。

原稿“查看比赛日”滚动到比赛日区，并聚焦当前日期；日期 `11.08`、`11.09` 和“赛果”切换本地示例列表。生产改为 API 数据日期，保留按钮尺寸、下划线选态和列表结构。日期按北京时间，待开始按时间升序，赛果按完赛时间倒序。

原稿导航和“比赛详情”部分是静态文字示意；生产必须替换成保持同样样式的真实链接，支持键盘和 URL 直达，不能留下假按钮。名单、积分、比分只读；真实业务变动后刷新，不乐观展示未确认的获胜结果。

原稿中 `Tweak`、方案轮播、临时示意舞台不是产品功能，不移植到生产。用户没有提交调色或密度修改，默认紧凑开关关闭，颜色按上表，不把可调项视为新需求。箭头图标用同名 Lucide（`arrow-down-right`），本地打包，装饰图形无需外部图片。

## 8. 动态内容、空态与允许变化

可以变化：赛事名、赛季、队伍数、阶段、焦点比赛双方、Logo、比分、地图、积分、日期、公告、真实版权信息；变化来自已配置业务数据。静态品牌与标题保持基准，除非用户明确改文案。

必须补充但不改设计语言：加载、网络错误、无比赛、无积分、队标缺失、长队名和无直播状态。无数据时不能继续展示示意队伍；缺失 Logo 使用队名缩写，保持队标尺寸。长名允许换行，不扩大比分区或挤出比赛状态。

参考包含“比分由赛事管理员更新”，保持这一事实，不加“游戏实时同步”等误导文案。当前示意中的 16 队、进行中、具体赛果均不等于正式赛事事实。

## 9. 视觉验收方法

本节视觉比较与测试统一安排在全部功能完成后的最后环节，不作为前面各开发阶段的测试门槛。

1. 从保存的片段建立参考页面；产品首页装载相同示例数据。不要拿不同内容比较像素。
2. 固定同一操作系统、字体、浏览器、缩放 100%、设备像素比、主题及内容区宽度，等待字体和图标稳定。
3. 分别比较宽 1024、760、540、390、320px；浅深主题各一组。断点两侧补看 761、541px，防止错用媒体查询。
4. 对照必须覆盖顶部品牌、主标题折行、右 GDUF 字形、木棉纹样、校训条、焦点比分、地图行、积分、日期选态、赛程与页脚。不能只比较首屏上半部。
5. 截图叠加或图像差分逐区排查；关键几何位置以 1～2 CSS px 内为目标，颜色 token 必须相同。字体抗锯齿差异单独判断，不能用它掩盖结构偏差。
6. 不同系统字体可能改变像素输出；严格复现采用同环境。更换字体、增大微型辅助字、改变对比度或重新排版均需记录为设计变更，不能声称与基准逐像素一致。

本次文档整理只验证源文件完整性、提取一致性、脚本语法和预览生成；尚无生产页面，因此不声称已完成产品视觉验收。
