# 单管理员与 Excel 导入规范

版本：V1.1｜2026-11-08

## 1. 管理员账号

只允许一个管理员。通过部署时初始化命令创建，不开放注册、新建管理员、角色分配和邀请接口。密码由操作者设置，不能在代码、镜像或文档内放默认生产密码；使用 Argon2 哈希。

登录成功建立服务端会话，Cookie 使用 HttpOnly、生产 Secure、SameSite；写请求进行来源与 CSRF 校验。退出销毁会话；修改密码使旧会话失效。登录限流，过期会话返回 401。忘记密码通过服务器受控命令重置，不引入其他用户账号。

## 2. 文件格式与模板

实施默认支持 `.xlsx`，不直接接收旧 `.xls` 或宏文件。提供带版本的模板下载；若组织者已有固定格式，适配后再冻结列名，当前不能声称已确认现有表格格式。

模板两个工作表，表头占第一行，不使用合并单元格。导入时先在后台选择赛事，文件不负责创建／切换赛事。

### 工作表：队伍

| 列名 | 类型 | 要求 |
| --- | --- | --- |
| 队伍编号 | 文本 | 必填，同届唯一稳定编号，例如 T001；修改名称不改变编号 |
| 队伍名称 | 文本 | 必填，去除首尾空格；同届同名作为冲突要求管理员处理 |
| 队伍简介 | 文本 | 可空 |
| 队长联系方式 | 文本 | 必填，后台私密；不强制只能填手机，可填 QQ／微信等 |

### 工作表：成员

| 列名 | 类型 | 要求 |
| --- | --- | --- |
| 队伍编号 | 文本 | 必填，引用“队伍”表 |
| 游戏昵称 | 文本 | 必填 |
| Steam ID | 文本 | 必填，统一 SteamID64；不收集账户密码 |
| 成员类型 | 枚举文本 | “正式”或“替补” |
| 是否队长 | 枚举文本 | “是”或“否”，每队恰好一名正式队长 |

建议系统生成 T001 等模板编号方便首次填写。编号在选定赛事范围识别，不依赖全站唯一。未来跨届复用使用数据库稳定队伍 ID，不凭同名自动关联。

Steam ID、联系方式、队伍编号预设文本格式。Excel 数值最多保留 15 位有效数字，因此 Steam ID 遇到数值单元格一律报错，要求重新提供原始文本；后改成文本无法恢复已损坏的数字。验证只能确认格式和唯一性，不能在没有 Steam 接口的情况下宣称账号真实存在。

## 3. 导入交互

1. 选择赛事与“新增／更新”模式。
2. 上传文件，显示文件名、模板版本、赛事名称。
3. 服务端解析并校验，尚不写入正式业务表。
4. 展示队伍数、成员数、新增／修改／未变更数量、字段差异和错误定位。
5. 无错误时管理员点击“确认导入”。
6. 后端重新核对赛事状态、数据版本与唯一约束，一次事务提交。
7. 展示成功批次和变更汇总，刷新后台与公开缓存。

预览错误定位包含工作表、Excel 行号、列名、队伍编号、错误码和可执行原因。例如：`成员 / 第18行 / Steam ID / MEMBER_CONFLICT：该选手已在本赛事 T003 名单中。` 私密错误报告只在管理员端返回。

预览页明确声明：“当前仅预览，尚未导入”。不可在上传完成后立刻写入，再让管理员确认。

## 4. 校验矩阵

| 类别 | 校验与处理 |
| --- | --- |
| 文件 | 文件实际结构与扩展名相符；建议上限 5 MiB、32 队、224 名成员；限制解压后体积和行数 |
| 表结构 | 两个必需工作表和必需列存在；额外列提示忽略，不推测未知字段含义 |
| 单元格 | 必填、长度上限、枚举正确；纯空行可忽略；业务字段不接受公式／错误单元格 |
| 队伍 | 编号与名称不冲突，队伍数不超赛事上限 |
| 成员 | 五正式、最多两替补、唯一正式队长、昵称及 ID 非空 |
| 关联 | 所有成员的队伍编号存在，不能出现无队伍成员 |
| 文件内重复 | 同一 Steam ID 不能跨队或在同一队重复出现 |
| 现有数据 | 与本赛事其他有效名单冲突则报错；其他赛事可复用同一选手 |
| 状态 | 赛事未锁名单；生成／发布赛程后成员变动按专用流程处理 |

所有数据限长及文件上限为实施默认，须在接口 schema、模板说明和页面提示中一致。读取库使用 openpyxl，不执行 Excel 公式和宏，不下载外部链接。

## 5. 新增、更新与幂等

新增是默认模式。文件中编号已存在则阻止提交，不猜测覆盖意图。更新模式按 `competition_id + team_code` 匹配；未存在编号列为新增，存在编号展示字段差异。文件未出现的队伍不受影响。

更新名单以“该队完整五至七人列表”替换，不把表内成员误解为增量。预览需特别列出被移除的成员，且先校验最终整体名单再写入，允许合法的跨队调整而不因中间步骤暂时冲突。

建议保存 30 分钟有效的预览批次：文件哈希、解析结果、赛事版本、模式、操作者、到期时间及状态。确认携带预览批次 ID 和幂等键；同一批次重复确认返回已有结果，不重复创建队伍。

预览后任何名单变动使版本失效，返回 409，提示重新预览。确认过程锁定赛事名单修改入口，防止另一窗口并发更新破坏校验结论。

## 6. 事务、撤销与历史

小规模导入全部成功或全部失败，不提供悄悄跳过错误行的模式。一次事务包含参赛记录、成员快照、当前有效占用、批次结果和审计记录。数据库异常回滚后返回明确错误，保持原名单不变。

名单发布／比赛开始后不允许普通更新模式替换参赛成员。专用变更流程要求原因、版本记录和影响提示；既有比赛引用的名单快照不变。

撤销队伍先检查分组、比赛及成绩引用。未排赛可撤销有效参赛资格并释放选手占用；已有关联数据时禁止直接硬删除，需先处理赛程。首次版本不承诺一键回滚任意历史导入批次；修正走显式名单操作并留日志。

## 7. 公开显示与日志

成功录入的有效名单可在已发布赛事下显示，不增加重复审核步骤。导入文件、联系方式、Steam ID、内部备注与差异报告不公开。

导入历史保存批次 ID、赛事、模式、时间、文件名、文件哈希、数量、结果、错误汇总及操作者。原文件是否长期保留、保留期限需组织者决定；默认解析后按短期清理策略处理，不能存入可公开访问的 uploads 目录。审计需要的变更快照也只允许管理员查看。
