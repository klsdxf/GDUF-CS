# 产品范围与业务模块

版本：V1.1｜2026-11-08

## 1. 产品定义

“广金主场”是面向广东金融学院学生的轻量 CS2 赛事展示与管理平台。定位为学生社团赛事平台，不把示意页面描述为学校官方赛事网站。正式赛事名称、主办方及校徽使用素材以组织者最终提供的信息为准。

目标规模沿用 PRD：16～32 支队伍、约 100 人同时访问、约三个月使用周期。现金预算 0～100 元是目标，不是已核实的生产报价。

业务闭环调整为：管理员创建赛事 → 手动录入／Excel 导入 → 名单确认并展示 → 配置分组与赛制 → 预览并发布赛程 → 录入并确认成绩 → 自动积分与晋级 → 公众浏览 → 赛事结束归档。

## 2. 权限边界

| 操作 | 游客 | 唯一管理员 |
| --- | --- | --- |
| 浏览已发布赛事、名单、规则、赛程、比分、公告 | 允许，不需登录 | 允许 |
| 观看已配置直播、访问回放 | 允许，不需登录 | 允许 |
| 查看联系方式和 Steam ID | 禁止 | 允许 |
| 修改赛事、队伍、成员、比分、内容 | 禁止 | 允许，后端鉴权 |
| 导入 Excel、查看导入差异及错误报告 | 禁止 | 允许 |
| 注册账号、提交线上报名、评论、聊天 | 不提供 | 不提供 |

不因只有一个管理员而删除会话管理、输入校验、审计或并发保护。同一管理员可能同时打开多个窗口。

## 3. 赛事管理

维护名称、简介、赛季、组织方、规则正文、参赛上限、名单整理窗口、地图池、赛制阶段、直播信息。比赛时间统一存带时区时间，界面显示北京时间。

建议状态：`draft` 草稿 → `roster_preparation` 名单整理中 → `scheduling` 赛程准备中 → `ongoing` 进行中 → `completed` 已结束 → `archived` 已归档。这是替代旧“报名中／报名结束”的实施默认，不再显示在线报名入口。

草稿不公开。发布前检查名称、规则和必要配置；阶段开始前检查名单、赛程与晋级规则。已产生比赛数据的赛事不能直接删除；归档保留记录，特殊修正留原因。

## 4. 参赛名单与战队档案

手工录入和 Excel 导入必须调用同一业务服务。每队五名正式队员、最多两名替补，队长建议选自正式成员；同一赛事内同一 Steam ID 只能占用一个有效参赛名额。

录入成功即视为管理员已确认，不再设置第二次业务审核。赛事已发布时，有效参赛名单可公开展示；赛事未发布时仍只在后台可见。

公开：队伍名称、Logo、简介、游戏昵称、正式／替补身份、比赛成绩。私密：联系方式、Steam ID、导入文件及管理备注。不能只在页面隐藏，公开 API 本身也不得返回私密字段。

当届队名、Logo 引用和成员资料保存快照；历史比赛绑定当时名单版本。跨届复用队伍资料不能重写上一届档案。Logo 可在后台单独上传。

## 5. 赛制、分组与赛程

V1 保留单败、小组循环赛＋单败、标准双败三种模板；支持 BO1／BO3／BO5、单／双循环、随机／手动／种子混合分组及可选季军赛。

流程：选择有效队伍 → 设置阶段与参数 → 生成草稿预览 → 调整种子和分组 → 检查 → 发布。生成对阵和分配比赛时间分离；直播资源、同一队伍时间冲突需检查。随机抽签记录种子及最终结果，不能悄悄重复抽签覆盖已发布结果。

发布后不允许一键重新生成覆盖已有比赛。未发布草稿可明确作废后重建；生成请求需幂等，避免双击产生两套赛程。

晋级关系显式保存“来源胜者／败者 → 目标场次 A／B 位”。小组名次到淘汰赛的位置也需明确映射；小组结束且排名无歧义后确认晋级名单，不根据暂时积分提前晋级。

非二次幂人数按已配置种子和轮空规则生成，轮空不是比赛胜利，不产生虚构地图比分。首届的跨组种子与双败总决赛是否重置仍待确认。

## 6. 比赛结果、排名和修正

比赛生命周期：待安排、待开始、进行中、已结束、已延期、已取消。正常完赛／弃权／技术判负以独立 `result_type` 表达，避免把异常结果和生命周期混成一个字段。

管理员填写地图、非负整数回合数、加时标记和备注。后端计算地图胜者与系列赛胜者；达到 BO 所需胜场才允许正常完赛。不能在系列赛结束后继续追加有效地图，不能让前端提交的 `winner_id` 覆盖计算结果。

成绩区分草稿与正式确认。正式确认后才影响积分与晋级。弃权或技术判负单独录入胜者、原因和统计口径，不伪造 13:0 等实际未发生的地图。

默认无平局、胜 3 分负 0 分；依次比较积分、相互战绩、地图净胜差、回合净胜差，最终管理员有理由裁定／抽签。多人同分小积分规则须在发布赛事前确定。排名未决时显示并列／待裁定，不能用数据库 ID 冒充正式排名。

小规模阶段优先从正式有效结果重新聚合积分、战绩，避免修改结果时重复加分。前台不允许直接编辑积分。正式修正必须填写原因并预览受影响后续比赛：尚未开始的可事务内撤销旧晋级并重算；已开始／结束的必须先显式处理，禁止静默替换参赛队伍。

## 7. 直播、公告和首页数据

直播由 B 站承担，网站不转发视频流。保存直播间、管理员维护的直播状态及回放；官方允许的嵌入方式经实际测试后启用，始终保留跳转入口。不能因赛事进行中就自动宣称直播在线。

公告支持草稿、发布、修改、置顶、计划发布时间和图片；只返回已到发布时间的公开内容。历史赛事及公告使用稳定 URL。

首页焦点比赛由管理员指定，失效时按公开比赛状态和开始时间选取。没有进行中比赛时显示下一场；没有赛程时显示“赛程待公布”，不能继续展示示意中的虚假赛况。首页比赛日、参赛队数、阶段、积分均来自后端。

## 8. 保留的非目标

不自建 CS2 游戏服务器、推流／视频分发、选手实时数据采集、语音、社区、商业收费、AI 解说或 Steam 自动数据获取。本轮 Excel 支持队伍和成员；比分和赛程批量导入不在已确认范围内。
