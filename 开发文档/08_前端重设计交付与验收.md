## 验证方法

Windows、本机 Edge、100% 缩放、DPR 1，参考与 Vue 使用同一浏览器环境和本地素材。覆盖首页宽度 1920、1600、1599、1051、1050、761、760、390、381、380、320，两种强调色；其他所有页面分别比较 1440 与 390 的两种强调色。补充导航、公告／名单弹窗、地图切换和页脚差分。

截图必须尺寸相同。细微字体／GPU 栅格舍入单列：每通道差值上限 4/255，超过 1/255 的像素不超过总面积 0.1%；不通过修改参考或扩大布局误差通过验收。CSS 颜色与布局值仍来自冻结源文件。详细测量将随最终测试结果保存。

## 本地验证与复现

- `npm run build`：demo 与 api 两种构建均检查 TypeScript 并打包。
- `.venv/Scripts/python -m pytest -q backend/tests`：34 项通过，包含原三种赛制、结果、导入、隐私等既有回归；有一个原依赖的弃用提示。
- 独立 SQLite 验收库 `storage/redesign-acceptance.db`：不入库。后台浏览器闭环通过：创建／发布赛事、Excel 预览与整批导入、阶段种子、生成与发布赛程、地图草稿、正式确认。
- 独立真实 API 模式页面读取该验收库：赛事、完整对阵、正式赛果、当场名单与战队深链接通过；检查公开内容未包含联系方式及 Steam ID。
- Playwright 默认套件：自动启动 demo（5173）、api（5176）、冻结稿回环只读服务（4175）。默认不启动后台验收库；真实后台测试通过 `E2E=1` 及 `E2E_BASE_URL` 显式启用，真实公开 API 集成通过 `E2E_PUBLIC_BASE_URL` 指定已准备的隔离实例。
- GitHub Actions 增加前端浏览器和视觉报告任务；原后端／部署／备份恢复 CI 保留。远端执行结果以实际 Actions 为准。

## 数据模式与交接

开发时在 `frontend/.env.local` 中选择 `VITE_PUBLIC_DATA_MODE=demo|api`；Docker Compose 根目录环境中使用同名变量传给 web 构建。切换后重建前端，不能仅改运行环境就假定静态文件已切换。

管理后台始终连接真实后端，演示前台不会替管理员写入数据。真实赛事准备好后按原流程维护／发布，再使用 api 模式。默认提交包含用户要求保留的示例展示；本轮未部署生产，也未向生产播种示例。
