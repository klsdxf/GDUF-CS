# 冠军纪念章鼠标动画初始化缺陷修复技术计划

日期：2026-11-10（Asia/Shanghai）

版本：V1.0

定位基线：`e3d99bd`

状态：已实施修复并完成本地专项验证；实施结果见第 10 节。前九节保留计划编制时的依据与验收要求。

## 1. 问题与目标

最终排名页首次进入后，鼠标在冠军纪念章区域移动，纪念章没有随指针倾斜；点击下方冠军、亚军或季军奖品标签切换到其他名次后，再返回纪念章区域移动鼠标，倾斜交互恢复。

本问题属于前端交互初始化缺陷。当前没有证据表明它涉及权限绕过、数据泄露或后端安全问题。

修复目标：在支持悬停与精细指针的桌面设备上，结果主体首次渲染完成后即可响应鼠标移动，无须先切换奖品；后续奖品切换、赛事切换和组件重新进入后仍可正常使用。

## 3. 根因与调用链

相关代码位于 `frontend/src/Results.vue`，行号以定位基线为准。

| 位置 | 行为 | 与缺陷的关系 |
| --- | --- | --- |
| 第 15 行 | `html` 根据 `data`、`selected` 计算完整结果页 HTML | 奖品选择也会触发完整结果主体重新生成 |
| 第 17–25 行 | 路由监听使用 `immediate: true`，立即执行 `load()` | 演示数据及传入的预览数据同步赋值，发生在 HTML 监听注册之前 |
| 第 28–32 行 | `animate()` 绑定 `pointermove`、`pointerleave`，创建滚动显现观察器 | 只有执行此函数，纪念章才具备指针倾斜交互 |
| 第 34 行 | 普通 `watch(html, ...)` 在变化后等待 `nextTick()`，执行 `filter()` 与 `animate()` | 没有首次挂载入口，也没有立即执行选项；已经存在的首次 HTML 仅被当作监听初始值 |
| 第 39 行 | 奖品点击更新 `selected` | 触发 HTML 变化，间接补上动画绑定，因此出现“切换后恢复” |

首次进入演示页的顺序：

1. 组件执行初始化，立即路由监听触发 `load()`。
2. `demoData()` 同步返回，`data` 与 `loading` 在当前调用中完成赋值。
3. 随后注册 `watch(html, ...)`，它读取当前 HTML 作为初始值，不执行回调。
4. Vue 挂载结果主体，但没有对应的首次动画初始化调用。
5. 切换到其他奖品后，`selected` 改变，HTML 变化监听才执行，绑定鼠标事件。

即使 `load()` 声明为 `async`，演示数据和 `previewData` 分支没有执行 `await`，不会因此推迟赋值。

## 4. 影响范围

| 场景 | 源码推导 |
| --- | --- |
| 演示模式直接打开 `/results` | 存在首次初始化遗漏 |
| 演示模式直接打开 `/results/autumn` | 使用相同组件与同步加载分支，存在同类遗漏 |
| 从其他前台页面首次进入最终排名 | 若新挂载 Results 组件，存在同类遗漏 |
| 后台传入 `previewData` 的内部预览 | 同步赋值，存在同类遗漏，需要专项验收 |
| 真实 API 异步加载成功 | 监听通常已在响应返回前注册，因此通常能够触发初始化；修复须保持此路径有效 |
| 奖品切换 | 更换 HTML 后必须重新绑定到新节点，不能只修复首次挂载 |
| 滚动显现 | 与鼠标动画共用 `animate()`，首次绑定也可能遗漏；需一并检查，无须改变视觉设计 |
| 触摸设备 | 现有媒体条件会跳过指针倾斜，不能将触摸设备不倾斜判为本缺陷 |

离线导出使用独立的 `results/offline.ts`，当前没有同等的指针动画绑定实现。本次不将离线动画能力扩展纳入修复，仅回归已有导出、搜索、切换与弹窗功能。

## 5. 推荐修复方案

采用“首次挂载初始化 + HTML 更新后重新初始化”的小范围方案，保留现有模板、CSS 和鼠标倾斜算法。

### 5.1 统一 DOM 同步入口

在 `Results.vue` 提取统一函数，例如 `syncResultDOM()`，集中执行以下步骤：

1. 等待 `nextTick()`，确保 `v-html` 内容和模板引用已经更新。
2. 确认组件仍然有效，根节点存在；若已经卸载，直接返回。
3. 将当前搜索词恢复到搜索输入框，并调用既有 `filter()`。
4. 调用 `animate()`；清理旧绑定后，对当前结果节点绑定交互。

该函数由两个入口调用：

- `onMounted`：覆盖同步数据首次渲染，不依赖 HTML 后续变化。
- 现有 `watch(html, ...)`：覆盖 API 数据到达、奖品切换和后续结果 HTML 更新。

不要将动画初始化放进奖品点击处理器，也不要使用固定延时等待页面。仅增加 `watch` 的立即执行选项而不核对挂载时机，也不能作为验收依据。

### 5.2 清理与重复调用

保留当前先清理、后绑定的模式：取消旧 RAF、断开旧 IntersectionObserver、移除旧节点事件，再建立新绑定。

完善以下约束：

- 清理函数应可重复调用，清理后将 `dispose` 重置为空函数。
- 使用组件有效状态和同步任务序号保护异步 DOM 同步：新调用使旧调用失效，卸载时使尚未完成的调用失效。
- 卸载时继续保留原有请求序号失效、定时器清理与动画资源清理。
- 加载、错误或无结果状态下允许安全清理并返回，不为缺失节点创建监听器。
- 同一次 DOM 更新若触发多个入口，最终只能保留一组有效事件绑定与观察器。

### 5.3 保持现有交互参数

保留桌面媒体条件 `(hover:hover) and (pointer:fine)`、页面隐藏检查与 RAF 合并逻辑。

保留默认 `rotateX(7deg)`、`rotateY(-13deg)`、`rotateZ(-8deg)`，以及当前相对纪念章场景计算的倾斜幅度。鼠标离开恢复默认角度。保留入场、扫光、光晕和高光动效的样式与时长。

本次不拆分整页 `v-html` 渲染、不重构奖品模块，也不调整 API 轮询、发布快照或后台数据逻辑。若验证发现独立缺陷，另行记录后确定范围。

## 7. 集中验证计划

按项目开发原则，先完成全部修复实现，再集中审查、补充测试并执行验收。本轮仅制定计划。

### 7.1 核心回归用例

新增独立用例，在页面首次加载后、任何搜索、奖品点击、键盘切换或弹窗操作之前验证鼠标交互，避免其他操作提前触发初始化。

测试使用固定桌面视口，例如 1280 × 900，并确认精细指针媒体条件成立。将鼠标先移到冠军区域外，待结果主体可见后，在纪念章内两个不同位置移动，轮询检查：

1. `.v5-seal-object` 的内联 `--seal-rx`、`--seal-ry` 已被设置。
2. 两个不同位置产生不同的倾斜变量值，且符合当前计算公式的方向。
3. 鼠标离开纪念章场景后，两项内联变量被移除，回到默认样式。
4. 切换奖品并返回纪念章后，上述行为仍然有效。

断言以鼠标处理器实际写入的变量为主，辅以最终 transform 检查。不仅比较入场前后的 transform，避免将 CSS 动画或视口变化误判为鼠标交互成功。等待采用状态轮询，不依赖任意固定延时。

## 10. 实施与验证记录（2026-11-10）

### 10.1 实际修改

- `Results.vue` 增加 `onMounted(syncResultDOM)`，覆盖演示与内部预览的同步数据首次渲染；HTML 变化监听复用同一入口，保留 API 加载和奖品切换后的重新绑定。
- DOM 同步等待 `nextTick()`，用同步任务序号淘汰旧任务，并在组件卸载后停止后续绑定；清理后重置 `dispose`，保留 RAF、观察器、事件和定时器清理。
- 新增 `tests/seal-motion.ts`，直接检查两处鼠标位置产生的倾斜变量与离开后的恢复行为，避免入场动画造成假通过。
- 演示页新增首次进入、历史页、反复奖品切换、站内离开重进、刷新与触摸设备检查。测试期统计冠军区域事件绑定，切换后保持一组，离开后归零。
- 真实 API 用例增加内部预览连续开关两次、受控延迟加载、503 后重试及恢复后的首次鼠标交互；切回后台时显式激活后台标签页后再执行撤回。
- 视觉测试先等待结果主体出现，再等待字体加载完成，消除异步组件尚未挂载时提前测量造成的窄屏差异。未修改视觉阈值、冻结稿或产品 CSS。
