# GDUF CS 前端重设计开发方案

版本：V1.0｜确认日期：2026-11-09｜时区：Asia/Shanghai

> **开发原则：先专注功能实现，最后一轮再统一审查与测试代码。**
>
> 实现阶段集中完成页面、交互、数据模式和现有业务接入，不穿插代码审查、测试编写或测试执行。全部功能完成后，集中进行代码审查、测试、问题修复和最终验收。保留现有安全与业务约束，不借重设计删除已有能力。

## 1. 本轮确认与交付范围

用户已经确认本轮实际编写并在浏览器展示的独立前端预览，要求正式前端与示例页面**一模一样**。确认对象不是图片稿，也不是此前米白／红色的“广金主场 · 观赛优先”。

最后确认的修改包括：

1. 保持首页 AUTUMN／2026 主标题、人物背景、按钮、各区块位置及总体布局不变。
2. 主视觉右下角增加 `G/`＋`GDUF CS` 品牌组合，沿用当前强调色及英文院校辅助行。
3. 移除“广东金融学院 · 学生社团赛事”及页脚对应完整字样；顶部品牌下的留白保留，不因删字改变导航几何位置。不得重新加入同一句宣传说明。
4. 默认采用竞技蓝；保留预览已经提供的荧光黄切换效果。
5. 保留示例赛事、队伍、比分、赛程、名单和公告，先随首版提交／推送，后续按实际赛事内容修改。

本次交付是**开发文档＋原样冻结的前端基准＋示例数据归档**，不在本轮直接改造 `frontend/src`、后台、数据库、线上配置或生产服务。推送这些文件不等于新版业务前端已经接入或上线。

## 2. 视觉权威、版本及禁止事项

唯一现行基准目录：

```text
开发文档/前端设计基准/GDUFCS_2026重设计_已确认/
  index.html
  style.css
  app.js
  assets/
  示例赛事数据.json
  设计基准清单.json
  README.md
```

`index.html`、`style.css`、`app.js` 与素材从用户最后确认的本地预览原样复制；不得重写基准来迁就产品实现。哈希记录见清单。后续获批修改另存版本并记录，不覆盖本次确认版本。

优先级：用户后续明确指示 > 本文件及本轮确认记录 > 本轮冻结源码／资源 > 其余业务文档 > 历史视觉文档。涉及具体字体、颜色、间距、结构、断点、交互表现时，以本轮冻结源码为准；说明中的概括不能用来“做一个相似的”。

旧版红色主视觉、中文大口号、木棉花瓣、顶部院校条、校训、四栏目导航及系统浅深色切换均不再是本轮视觉要求。旧资产保留用于追溯，不能与新稿混搭。PGL、ESL、IEM 是设计研究来源，**不是**后续继续自由改版的授权；当前选择已经落实为具体页面。

## 3. 页面与路由

预览使用 hash 路由仅为独立文件演示。正式产品继续使用现有 Vue Router 和稳定业务 URL；改变地址机制不改变页面外观。已有赛事、比赛、战队及公告链接必须继续有效。

| 已确认预览入口 | 正式页面／入口 | 实施要求 |
| --- | --- | --- |
| `#home` | `/` | 改为平台门户，不再直接复制默认赛事首页 |
| `#events` | `/competitions` | 赛事目录，当前赛事与历史赛事，年份筛选 |
| `#event` | `/competitions/:slug` | 当届赛事概览，与平台首页分开 |
| `#event/schedule` | `/competitions/:slug/schedule` | 日期切换、比赛列表、晋级对阵入口 |
| `#event/standings` | `/competitions/:slug/standings` | 分组积分及晋级说明 |
| `#event/teams` | `/competitions/:slug/teams` | 战队卡片及当届名单入口 |
| `#match`、`#match/upcoming` | `/matches/:id` | 已完赛、待开始状态；逐图赛果与当场名单 |
| `#news` | 平台公告聚合入口 `/announcements` | 沿用已发布公告接口组合读取，不新增后台内容体系 |
| 公告弹窗 | `/announcements/:id` | 保留原稳定链接；列表点击可用可深链接的弹窗实现 |
| 战队名单弹窗 | `/competitions/:slug/teams/:id` | 保留原稳定链接；弹窗和直接进入均可阅读 |
| `#event/rules` | `/competitions/:slug/rules` | 长文本、参数、地图池的已确认布局 |
| 直播／回放按钮及弹窗 | `/competitions/:slug/live` | 有配置显示真实入口，无配置保持真实空态 |

`/announcements` 是本次信息架构所需的前台聚合页，不要求新增后端聚合接口。第一版可以按已发布赛事查询已有公告接口，在前台合并已发布内容并排序。现有当届公告路径 `/competitions/:slug/announcements` 继续保留。

静态稿的历史赛事详情仅展示归档占位说明，不代表可删除既有历史赛程、积分、名单、规则或比赛记录。正式接入后，历史赛事必须能浏览已有真实内容。

## 4. 必须照搬的页面构成

### 4.1 公共外壳

顺序：顶部演示说明／配色条 → 黑色品牌导航 → 页面主体 → 黑色页脚。主导航为“首页、赛事、赛程、战队、公告”，右侧观看直播；左侧 `G/` 及 `GDUF CS`。删除中文说明后保留 `.brand-spacer` 的几何占位。

演示模式保留当前的示例声明和配色控制，不能为“生产感”擅自删掉。改为真实数据时，可将有关“设计预览”“不连接接口”的事实说明换为准确的实际运行说明，属于内容状态变化；不能因此重排导航、页脚和主体。当前稿没有管理员入口；正式实现需保留 `/admin/login`，如增加页脚低调“管理”文字入口，须在最终差异表明示该必要功能补齐，不声称参考文件原本已有此入口。

### 4.2 平台首页

1. 大幅主视觉：左侧 `GDUF COUNTER-STRIKE 2`、`AUTUMN`／`2026`、中文赛事名、日期与状态、进入赛事／查看赛程。
2. 右侧官方 CS2 游戏画面、既有暗色遮罩及斜线细节；右上赛季编号，右下确认过的 GDUF CS 品牌组合。
3. 下一比赛日横条：时间、双方、BO／阶段和详情入口。
4. 浅色赛事目录：年份切换、三张示例赛事海报、状态与日期；窄屏按基准重排。
5. 白色公告区：左标题／入口、右侧日期与标题列表。
6. 公共页脚。

不把主视觉替换成旧版口号，不加入新统计卡片、霓虹效果、额外宣传段落，不交换赛程和赛事目录的位置。

### 4.3 当届赛事页

面包屑 → 当届横幅及参数 → 赛事导航 → 对应正文。概览左侧焦点对决，右侧积分；下方比赛日程。赛程、积分、战队、规则复用相同赛事外壳，保持切换后的信息层级与空间关系。

赛程列表与晋级对阵按钮保留。预览的晋级结构说明只是一种展示状态，正式页面必须接回已有完整对阵图、阶段与来源关系，支持原有三类赛制，不能把业务对阵图永久缩减成文字占位。

### 4.4 比赛详情

面包屑 → 赛事／时间／BO 与状态 → 双方队标、队名和系列赛分 → 地图比分条 → 浅底逐图赛果 → 双列当场名单 → 返回赛程。

已完成比赛支持地图按钮切换，展示地图回合分、胜者、加时状态。待开始比赛展示时间、阶段、BO 和等待信息，不显示未来赛果。暂无直播或回放时保留弹窗空态；不得添加假播放器。

## 5. 精确样式及素材

所有值以冻结的 `style.css` 及其最后追加的首页身份微调规则为准。以下仅为定位关键项，不替代完整源文件：

| 项目 | 基准 |
| --- | --- |
| 基础底色／面板／浅色区域 | `#101216`／`#191c22`／`#f1f2f2` |
| 竞技蓝强调色 | `#76b9ff`；按钮前景 `#102035` |
| 荧光黄强调色 | `#d9fb69`；按钮前景 `#1b2610` |
| 展示字体 | 本地 `Barlow Condensed`，500／600／700／800／900，各字重原文件保留 |
| 中文字体 | 保留稿件字体栈和系统回退；不自行替换字体 |
| 桌面导航 | 94px，水平内边距 4.5%；品牌与导航的既有尺寸和留白 |
| 主视觉 | 最小高度 565px；右侧图片占 69%，起始位置 31%；实际高度可被正文撑开 |
| 首页标题 | `clamp(88px,10.8vw,165px)`，800，行高 `.82` |
| 大屏 | `min-width:1600px` 的现有覆盖 |
| 其他断点 | `max-width:1050px`、`760px`、`380px`，逐条保留 |
| 右下品牌锚点 | `bottom:35px;right:5.5%`；移动断点覆盖按原稿 |
| 表格／列表／按钮 | 直角、字号、线条、留白和状态按原 CSS；不套用 Element Plus 默认样式 |

`assets/fonts.css` 与字体已本地保存。当前部分字体虽以 `.woff2` 命名，文件及样式声明沿用已确认预览，不擅自转码或改名影响还原。游戏图来自 Valve 官方商店截图；素材来源见清单。逐图赛果中的配图是布局占位，不保证对应地图实景，首版保留当前说明。后续实际素材替换记录为内容更新，不悄悄调整裁切和遮罩。

预览未提供真实队标，使用字母标记和切角底形。正式版本有队标时使用既有上传资源，没有队标时维持该占位表现。

## 6. 示例数据保存、首版推送与后续替换

### 6.1 保存内容

`示例赛事数据.json` 保存从冻结 JS 提取的队伍、昵称、公告、日期、赛程、地图名称，以及单独整理的赛事目录、A 组积分、焦点赛果、字段顺序和初始界面状态。**原始 `app.js` 同时保留全部模板与演示数据派生逻辑**，二者共同构成可复现档案。

默认：竞技蓝、首页、赛事年份“全部”、比赛日 11.14、逐图第 1 张、列表视图。焦点比赛：11.08 19:00，木棉 FIVE 对金融风暴，BO3，系列赛 2:1；Inferno 13:8、Mirage 9:13、Ancient 13:10。

数据完整性边界必须如实保留：

- 页面赛事参数显示 16 支队伍，但原稿只制作了 8 支示例战队；不为凑数擅自补出另外 8 队。
- 当前仅提供 A 组 4 队积分，其余组没有示例排名。
- 历史赛事只有封面、名称、日期和状态，没有历史赛果；不复制当前赛果冒充历史。
- 其他比赛详情中的地图比分、部分昵称来自演示逻辑；不是每场比赛都有独立、可信的完整赛事记录。
- 没有真实联系方式、Steam ID、账号、口令及可直接导入后端的完整赛制对象。

### 6.2 首版使用方式

先把本次文档、静态基准、素材与 JSON 推送至仓库保存。后续实现新版 Vue 前端时，将已保存数据映射为独立的演示数据适配器，首版允许使用这些示例内容展示与交付，**不要求先等齐真实赛事资料**。不能因旧规范写了“示例不得发布”而自行删掉用户本轮明确要求保留的示例内容。

推荐使用一个明确的前端构建配置 `VITE_PUBLIC_DATA_MODE=demo|api`。这是实施默认，不是现有工程已具备的开关：

- `demo`：从固定示例资源读数据，保留示例标识，管理后台仍接已有真实后端，不将任何演示数据写入数据库。只对已有演示页面暴露演示 ID，不把演示 ID 发送给真实写接口。
- `api`：通过现有公开 API 读取已发布内容；空数据和错误展示真实状态，不偷偷回退到示例比分。

模式应在站点启动／构建时明确选定，默认首版演示交付可选 `demo`，不是按“数据库是否为空”自动决定。一个页面中的队伍、比分和排名必须来自同一数据模式，禁止真假拼接。首版示例交付不要求伪造 Steam ID、后台录分事务或真实晋级边以完成数据库播种。

### 6.3 后续实际内容替换

实际赛事资料齐备后，管理员通过原有后台创建／发布赛事、导入或维护名单、配置赛制、发布赛程、确认成绩、维护公告与直播。前台切换到 `api` 模式，海报、标题、赛季、队标等改用已配置内容；参考布局、字号、背景裁切与交互维持一致。

冻结示例及基准继续保留，供未来还原比较，不以真实内容覆盖归档。正式业务要使用后端计算的比分、排名和晋级，不把静态 JS 中的演示推导迁移为真实算法。无封面字段时可先用按赛事 slug 配置的前端静态素材映射，不扩展为新的 CMS。

本轮“先推送”授权保存和提交源码／文档，不等于授权清空、重建或覆盖线上数据库；不在本次文档任务启动生产示例播种或线上部署。

## 7. 现有功能必须保留

后端接口、数据库结构及权限模型以现有实现为基础：游客免登录、单管理员、Excel 预览／整批导入、名单版本、三类赛制、BO1／3／5、分组与种子、轮空、晋级图、地图草稿与正式确认、异常结果、积分计算与同分处理、修正影响、公告、B站直播／回放、归档与审计均保留。

管理后台继续使用现有 Element Plus。公开新样式限定作用域，不能污染管理页面。公开字段白名单、Cookie／CSRF 和管理员接口鉴权继续生效。本轮只更换前台展示与读取组织，不重写一套计算胜负或晋级的前端逻辑。

后台创建／导入／录分流程即使不出现在截图，也不能缩减。没有完整高保真稿的特殊业务状态，沿用已确认组件与设计语言，最后列入差异表，不擅自标为用户逐屏确认。

## 8. 实施顺序

| 阶段 | 工作 | 本阶段产物 |
| --- | --- | --- |
| R0（本轮） | 固化基准、归档示例、编写规范并提交／推送 | 文档、静态页面、资源、数据和哈希清单；不改业务程序 |
| R1 | 按原稿迁移公共样式、品牌、首页结构 | 新 Vue 页面及本地字体／图像资源 |
| R2 | 迁移当届赛事页、赛程、积分、战队、规则、公告及比赛详情 | 完整页面与预览同款交互；稳定业务路由 |
| R3 | 实现演示数据适配器、默认演示交付及真实 API 读取模式 | 可先展示示例的新版前台；后台与业务保留 |
| R4 | 完成剩余业务状态、对阵图、长内容、移动端和数据切换 | 全部功能实现完毕，可统一验收的版本 |
| R5（最后一轮） | 统一代码审查、编写及执行测试、集中修复与复测 | 审查结果、业务／视觉／响应式验收记录及交付说明 |

R1～R4 不穿插逐阶段测试或代码审查；实现中的必要数据阅读和文件保存不算提前开启最终测试轮。原有 CI 不因本规范擅自删除；文档／基准归档提交可标 `[skip ci]`，开发中的自动 CI 执行与最终验收应区分记录，不把其通过当作本轮视觉完成证明。

## 9. 最后一轮的验收要求

以下内容现在只定义，不在 R0～R4 提前执行：

1. 同操作系统、浏览器版本、100% 缩放、相同 CSS 视口、设备像素比、本地字体和示例内容，对冻结页面与正式演示模式逐区截图叠加／差分。覆盖整个首页、赛事概览、赛程、积分、战队、规则、公告／名单弹窗、待开始与已完赛比赛详情、地图切换和页脚。
2. 视口至少覆盖 1920、1600／1599、1051／1050、761／760、390、381／380、320px；默认竞技蓝必须与原稿一致，荧光黄也按已有规则比较。不能沿用旧版 540px 断点或浅深主题标准。
3. 主视觉标题折行、图片裁切、遮罩、按钮、右下品牌、删除中文后的留白、赛事卡片、表格及名单不能发生未经批准的差异。颜色和字体值保持一致；同环境以可达到的零结构差异为目标，抗锯齿差异单列，不用“差不多”通过验收。
4. 对演示数据模式检查每个示例入口、状态、筛选、配色、地图、名单和公告交互，以及未提供数据的真实空态。页面显示 16 队但只演示 8 队等原稿边界在报告中说明，不暗改原稿后宣称一致。
5. 对真实 API 模式执行现有完整业务回归，特别是三种赛制、Excel 导入、正式成绩、积分晋级、修正影响、隐私、历史深链接与无直播配置。后端不应因前台重构而丢失能力。
6. 检查真实空数据／请求失败不混入示例，模式切换不向真实后端写演示对象；管理员操作仍写真实管理端，结果展示始终以对应数据源为准。
7. 汇总全部必要扩展与原稿差异，逐项解释并交付；未经用户确认，不以“优化”理由改变已确认主布局。

## 10. 本轮状态

本轮只保存文档、当前已确认静态源文件、素材和示例数据，不宣称 Vue 新前端已经完成，不宣称新设计已通过最终视觉比较，不新增生产数据库内容。提交和推送结果以实际 Git 提交及远端分支为准，不把计划写成已执行。
