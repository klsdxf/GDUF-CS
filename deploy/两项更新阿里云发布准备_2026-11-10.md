## 3. 上线前只读核对与备份

先执行并保存结果；有本地改动、镜像／卷不明或数据冲突时先处理实际差异。

```bash
cd /root/gduf-cs
git status --short
git branch --show-current
git rev-parse HEAD
dc=(docker compose -f compose.yaml -f deploy/compose.ip.yaml)
"${dc[@]}" ps -a
"${dc[@]}" images
grep -E '^(PUBLIC_ORIGIN|VITE_PUBLIC_DATA_MODE|COMPOSE_PROJECT_NAME)=' .env || true
"${dc[@]}" exec -T db psql -U gduf -d gduf -c 'SELECT version_num FROM alembic_version;'
"${dc[@]}" exec -T db psql -U gduf -d gduf -c 'SELECT slug,status,published FROM competitions;'
"${dc[@]}" exec -T db psql -U gduf -d gduf -c 'SELECT username FROM admins;'
```

只查看管理员用户名，不导出密码哈希、会话或真实 `.env`。正式库必须使用正式管理员，不能使用 `review-admin/dataset-admin/results-admin/test-admin`；发现测试身份时先完成单管理员交接。不要复制本地验收数据库，不直接清空管理员表。四队测试业务资料按需求保留，与测试登录账号分开处理。

维护窗口内停止后台业务写入，保留一致备份和旧镜像：

```bash
umask 077
release_stamp="$(date -u +%Y%m%dT%H%M%SZ)"
release_backup="backups/pre-two-updates-$release_stamp"
bash scripts/backup.sh "$release_backup"
git rev-parse HEAD > "$release_backup/source-commit.txt"
git branch --show-current > "$release_backup/source-branch.txt"
cp -p .env "$release_backup/environment"
"${dc[@]}" images > "$release_backup/images.txt"
"${dc[@]}" exec -T web nginx -T > "$release_backup/web.conf" 2>&1
"${dc[@]}" exec -T edge nginx -T > "$release_backup/edge.conf" 2>&1
docker image tag "$("${dc[@]}" images -q api)" "gduf-api-before:$release_stamp"
docker image tag "$("${dc[@]}" images -q web)" "gduf-web-before:$release_stamp"
printf '%s\n' "$release_stamp" > "$release_backup/release-stamp.txt"
```

备份失败停止。受控保存含密钥的 environment 文件，至少另存一份。原证书、DNS、edge 入口不在本次修改范围。

## 8. 回退

发布失败先停止后续步骤、保存日志与现场，不执行 `down -v`、清库或盲目 downgrade。

- 纯前端／动画问题：使用备份记录中的旧 web 镜像和原模式恢复，再 reload web、edge。
- 后端问题：按备份中的 API／web 镜像、源码及环境恢复一致版本。004 为增量表／字段；是否保留新结构运行旧版须依据实际错误验证，不在故障时删表解决。
- 数据初始化或队标异常：保留批次和发布记录；先撤回错误公开版本或恢复合适发布，不删原有赛事。若必须恢复全库，向独立空库恢复备份并核对后切换，按现有交接流程操作。
- 数据恢复须连同媒体恢复，不能仅回滚代码来撤销本次新增业务数据。保存原环境，直到恢复实例验证通过。
