### 1.2 与报告判断的必要补充

1. **F-01 的非法颜色已在本地确认。** `reference.css:11` 存在 `#ffffff025`，实际为 9 位十六进制数字。
2. **项目已有视觉回归。** `frontend/tests/visual.spec.ts` 在多个宽度对比冻结稿；冻结稿本身含缺陷，因此“与原稿一致”未能发现这些问题。报告 R-2 中“没有截图对比测试”不适用于当前本地代码事实。
3. **安全头并非源码完全没配置。** `frontend/nginx.conf` 的 server 层已有 nosniff、Referrer-Policy、CSP，但 `/`、`/assets/`、`/api/` 各自声明 `add_header Cache-Control`，会影响父级 `add_header` 的继承。这是 F-11 的明确本地线索；实际生产配置还需用 `nginx -T` 核对。
4. **真实积分榜的问题更深一层。** demo 链接指向队伍列表；API 的 `table()` 仅输出队名文本，尚未生成队伍链接。后端积分行已经包含 `team_id`，可直接修复，无需新增业务字段。
5. **不能新增一个虚构直播状态来配合按钮。** 后端只接受 `offline/live/replay`，没有 `scheduled` 直播枚举；“直播安排”应由 offline + 有效直播间地址派生。
6. **HTTP 404 需要区分路径和资源。** Nginx 路由白名单可阻止未知路径回退，却不能判断合法路径形状下的不存在 ID。客户端加 noindex 也不会改变 HTTP 200，不能单独作为严格 404 验收完成依据。

## 3. F-01：比分区装饰字遮挡

### 3.1 根因与定位

`frontend/src/redesign/reference.css:11` 的 `.public-site .match-hero:before` 使用非法颜色，浏览器忽略后继承近白色。`.match-team` 已有 `z-index:1`，而 `.match-final` 只有定位，没有显式层级；应统一层级契约，而非只靠当前绘制顺序。

### 3.2 推荐修改

在原规则修复颜色，不另追加一条覆盖声明；同时加入以下明确层级。保持现有布局及品牌设计。

```css
.public-site .match-hero { isolation: isolate; }
.public-site .match-hero::before {
  color: rgba(255, 255, 255, 0.025);
  z-index: 0;
  pointer-events: none;
}
.public-site .match-team,
.public-site .match-final { position: relative; z-index: 1; }
```

长队名允许换行：队伍网格列设 `minmax(0, 1fr)`，队名 `overflow-wrap:anywhere`；比分列保留最低可读宽度。两位数比分样例用于压力测试，不改 BO 赛制或比分业务规则。若 360px 下仍拥挤，减小比分字距和列间距，不能遮住队名或用省略号删除整个队名。

### 3.3 验收

- 1280×720、768×1024、390×844、360×780：已结束、未开始、长队名、两位数比分样例可读且不重叠。
- 读取 `getComputedStyle(hero, '::before').color`，alpha 接近 0.025；队名及比分层级高于装饰层。
- 两种数据模式均验证；静态检查不再出现非法 HEX。

## 4. F-02：移动赛程丢失赛制、分组和状态

### 4.1 根因与定位

760px 媒体查询直接隐藏 `.fixture-meta`。该选择器同时用于 `demo.ts:31` 的 `fixtureRows()` 与 `data.ts:37` 的 `fixtures()`，也影响战队详情中的比赛记录。

### 4.2 推荐结构

保留一个完整比赛链接，内部改成有语义的状态与信息节点；状态不要仅作为 `.fixture-meta` 的尾部裸文本。

```text
19:00   [待开始]                                      ↗
木棉 FIVE                VS                 北苑竞技
11.14 · 北京时间          小组赛 · A组 · BO3
```

宽屏仍可用单行网格；≤760px 使用显式 grid areas 分为时间状态、对阵、附注三行。新增 `.fixture-status` 与 `.fixture-format`，在两套渲染中使用相同 class。原 `.fixture-meta{display:none}` 删除，避免旧断点继续覆盖。队名容器 `min-width:0`，长文本可换行，图标不挤占比分。

状态显示使用公共格式化函数，基础状态与赛果类型分开：

| 数据条件 | 显示 |
| --- | --- |
| `unscheduled` | 待安排 |
| `scheduled` | 待开始 |
| `ongoing` | 进行中 |
| `completed`，普通结果 | 已结束 |
| `postponed` / `cancelled` | 已延期 / 已取消 |
| `confirmed` 且 `result_type=forfeit` | 已结束 · 弃权 |
| `confirmed` 且 `result_type=technical` | 已结束 · 技术判负 |

不要给 `Match.status` 新增 forfeit 值。阶段名从已加载 stages 按 `stage_id` 关联；淘汰赛没有分组时显示阶段/轮次，不拼出“null 组”。未知状态采用“状态待确认”，避免输出 undefined。

### 4.3 验收

同一条数据在桌面与手机的状态、分组、BO 一致；覆盖上表全部状态和无开赛时间/未定队伍。断言节点可见、字号达标、无横向溢出。同时检查赛事概览赛程及战队弹窗比赛记录。

## 5. F-03：首页摘要隐藏比赛与分组

### 5.1 根因与模式差异

- ≤760px 的 `.ribbon-game:last-child{display:none}` 隐藏末场，单场数据也会命中。
- ≤1050px 的 `.ribbon-format{display:none}` 隐藏分组与 BO。
- demo 的 `home()` 硬编码两场；API 的 `renderApi()` 首页过滤状态后 `slice(0,2)`，未按日期分组，可能将两个比赛日混为“下一比赛日”。不能只删 CSS 而保留这个语义差异。

### 5.2 推荐方案：下一比赛日全部显示

保留“下一比赛日”标题。两模式都交给同一摘要渲染规则，手机纵向排列，桌面自适应多列；保留日期、时间、双方、状态、阶段/分组、BO。摘要标题显示“共 N 场”，另有“完整赛程”入口。不用 `:last-child` 隐藏数据，也不靠无提示横滑发现第二场。

API 算法：

1. 对 `home.matches` 取有有效时间的 scheduled/ongoing，按时间与 ID 稳定排序。
2. 使用 `Asia/Shanghai` 生成比赛日键；正在进行的场次优先选择其比赛日，否则选择当前北京时间日期及之后最近的比赛日。日期已过但状态仍 scheduled 的异常数据不当作未来比赛，可在完整赛程查看。
3. 显示选定日的全部候选场次及总数，不使用 `slice(0,2)`。该日若有已结束场次，可并入当日摘要并保留“已结束”标签，使“共 N 场”与实际集合一致。
4. 只有未定时间场次时显示“开赛时间待安排”并链接完整赛程；没有候选时显示“暂无后续赛程”。有取消/延期记录仍在完整赛程可见，不伪装成下一场。
5. demo 使用固定演示时钟/明确日期样例，不用真实系统日期让冻结示例随时间消失；0/1/2/3 场测试通过数据适配注入，禁止向生产播种。

CSS 将 label 与场次列表分开，手机 label 独占首行；比赛列表 `grid-template-columns:repeat(auto-fit,minmax(...))`，≤760px 单列。删除 760 与 1050 两个隐藏规则。

### 5.3 验收

0/1/2/3 场各有用例；单场不能消失，三场都能到达对应详情。测试跨日、UTC 与北京时间日期不同、多阶段、延期及空时间。760/761、1050/1051 边界与 360/390/768/1280 宽度都应保留格式字段。

## 6. F-04：直播按钮承诺与实际状态不符

### 6.1 根因

`Public.vue` 导航按钮固定写“观看直播”。`loadPublic()` 目前仅访问赛事 `/live` 子页时加载 live，其他页面不能直接用当前 `model.live` 判断“未配置”，否则会将“尚未请求”误认为“确无配置”。demo 的直播弹窗则固定为未配置文本。

### 6.2 推荐修改

新增纯函数 `resolveLiveAction()`（建议位置 `redesign/presentation.ts`），由导航、赛事按钮、弹窗共用。返回 `{kind,label,tone,url}`，先验证 URL，再决定可观看状态。

| 数据条件 | 导航文案 | 视觉等级 | 点击 |
| --- | --- | --- | --- |
| 加载未结束 | 直播信息加载中 | 弱化 | 等待或显示加载说明 |
| `live` + 合法 `room_url` | 观看直播 | 主按钮 | 打开直播弹窗，明确直播间入口 |
| `replay` + 合法 `replay_url` | 观看回放 | 次要 | 打开对应回放信息 |
| `offline` + 合法 `room_url` | 直播安排 | 次要 | 弹窗显示“暂未开播”与直播间入口 |
| 空数组或无可用链接 | 直播信息待公布 | 弱化 | 保留赛程替代入口 |
| 请求失败 | 直播信息暂不可用 | 弱化 | 重试，不声称无配置 |

配置为 live/replay 但缺少对应有效链接时，降级为“直播信息待公布”，不生成虚假观看入口；可记录供管理员检查的数据一致性提示。不得自动模拟开播。

API 模式为当前赛事补充 `/live` 只读请求。赛事页使用该赛事，比赛详情使用其 `competition_id` 对应赛事；首页用现有默认赛事选择结果，独立公告页若无所属赛事则使用明确的默认赛事上下文。直播请求与页面主要内容分离，失败不阻断赛程；按赛事缓存并随现有 30 秒刷新更新，避免每次点击都重复加载全部页面。延用 sequence 防止切换赛事后旧响应覆盖新状态。

多条直播记录：比赛详情优先匹配当前 `match_id`，其余页面按 live > replay > 已配置 offline 选择；同优先级用 ID 稳定排序，不假定不存在的更新时间字段。弹窗仍可列出其他条目。demo 通过本地适配提供同结构的未配置状态，测试另外三种状态时注入样例，不调用公开 API。

URL 校验继续限制 HTTPS、`bilibili.com` 或其子域，排除相似后缀域名及带账号密码的 URL；外链保留 `noopener noreferrer`。按钮文案变长后须与 F-10 一起验证 360px 顶部布局。

验收四个业务状态、加载/失败、错误地址、多赛事切换及刷新后的文案变化；按钮、弹窗、实际链接须一致。此项只涉及前端适配，不改后台直播状态枚举。

## 7. F-07：裸域解析、证书与跳转

### 7.1 修改位置与依赖

DNS 在域名服务商管理；TLS 在 edge。修改 `deploy/domain-https.conf`、`scripts/domain-https.sh`，部署时更新生成文件 `storage/ip-edge/domain.conf`。当前脚本仅接收一个域名并签发一个 `--domain`，只修改模板不能补齐证书 SAN。

推荐专用配置值为 `CANONICAL_HOST=www.gdufcs.fun`、`REDIRECT_HOSTS=gdufcs.fun`，脚本校验域名并为证书传入两个 `-d`。这是脚本配置设计，不改数据库或业务环境含义；`PUBLIC_ORIGIN` 始终保持正式 www 来源。

### 7.2 执行顺序

1. 上线前只读核对 DNS、实际 ECS 地址、现用证书、edge 完整配置和续期任务。报告中的 `47.76.165.241` 是历史观测，确认后再写 DNS。
2. 给裸域配置指向实际服务器的 A 记录；未提供 IPv6 服务时不添加 AAAA。等待权威及多个递归 DNS 返回预期记录。
3. edge 的 80 端口为两个域名保留 `/.well-known/acme-challenge/` 静态验证，其余请求跳至规范 www 地址。
4. 在原证书名称 `gduf-domain` 下扩展 SAN 到 www 与裸域，验证成功后再启用裸域 443；保存旧配置与证书恢复点，不覆盖仍在使用的 IP 配置。
5. 裸域单独建立 443 server，加载覆盖它的证书并 `return 301 https://www.gdufcs.fun$request_uri;`。www 443 server 正常代理 web。
6. `nginx -t` 通过后 reload，复测并执行现有续期演练。不要通过重跑旧 IP 初始化切换脚本配置域名。

服务器配置示意：

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name gdufcs.fun;
    ssl_certificate /etc/letsencrypt/live/gduf-domain/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/gduf-domain/privkey.pem;
    return 301 https://www.gdufcs.fun$request_uri;
}
```

以上只是需合并到现有配置的片段，证书与全局安全头仍按本文其他章节加载，不能直接覆盖整个入口文件。

### 7.3 验收与回滚

HTTPS 裸域 TLS 校验成功，返回 301，Location 保留路径及查询，例如 `/competitions/autumn/schedule?date=2026-11-14`；HTTP 裸域也指向规范 HTTPS www。www 首页、深链、API、后台登录不出现循环。证书 SAN 包含两个域名，续期验证成功。失败时恢复上一份 edge 配置并 reload；保留可用的 www 入口。DNS 回滚需考虑 TTL，不能承诺立即生效。

## 8. F-05：积分队名直达当届队伍

定位：demo `standingsTable()`（`demo.ts:24`）和 API `table(rows,c)`（`data.ts:39`）；后端 `results.py:standings()` 已返回 `team_id`。

demo 将 `#event/teams` 改为当前赛事的 `/competitions/{edition}/teams/{示例索引}`。索引只用于既有演示数据；优先由显式示例队伍 ID 映射到展示索引，不能把排序后的排名当身份。`stableLinks()` 能保留 event 后的路径，但新增链接仍需验证。

API 用 `r.team_id` 构造当届详情链接，复用 `teamLink({id:r.team_id},c)`；显示文本仍 HTML 转义。不能用姓名匹配、行号或 `rank` 构造 ID。测试夹具 `api-mode.spec.ts` 的 standings 数据需补真实存在的 `team_id`。

沿用 `Public.vue` 的 `returnTo`，从积分榜打开名单弹窗，关闭/Esc 回到原完整 URL，保留滚动位置；新标签页直达没有来源时返回当届战队列表。另测浏览器后退，避免路由关闭逻辑把 history 变成循环。API 战队详情已包含比赛记录，无需把报告的可选建议当成新增必修功能；demo 不补造该队赛果。

验收至少两队、同名不同 ID、排序后队伍、历史届次，确保不会串队或串届；键盘可打开、Esc 可返回。

## 9. F-06：任务页面移动首屏被海报占满

定位：demo `eventShell(tab)` 与 API `renderApi()` 的赛事外壳，共用 `.event-hero`。

推荐让概览继续使用海报，schedule/standings/teams/rules/announcements/live 等任务页使用明确的 `.event-header--compact`：展示赛事名、赛季、当前状态和必要的直播入口，不输出占满高度的海报标题。用真实 tab 决定布局，不用宽泛路径子串匹配；历史赛事任务页同样适用。手机模式目标标题栏约 80～120px，允许长名称自然增高，不能硬裁文字。

高度预算以 390×844 CSS 像素视口计算：全站导航约 115、面包屑约 48、紧凑标题约 100、赛事导航约 56、栏目及筛选约 130，仍应容纳一条完整比赛及附注。该预算是实现目标，最终以截图和元素边界断言为准。移除任务页海报后同步减少顶部空白，不用自动滚动或锚点跳转掩盖首屏问题。

验收：390×844 赛程列表模式打开后，日期与第一场完整比赛的底边 ≤ 844；空日显示明确空状态。长赛事名、字号增大和 360px 不溢出；积分/战队首屏能看到至少第一条实际内容。晋级图可独立滚动，不能把“赛程必须看到一行列表”的断言套到图模式。

## 10. F-08：传输、协议、图片与字体

### 10.1 gzip 与 HTTP/2

TLS 和公网传输由 `deploy/domain-https.conf` 的 edge 层负责，推荐在那里集中 gzip 与 HTTP/2；web 保持来源资源分流，避免两层重复压缩策略。

```nginx
# 合并至正式 www HTTPS server；裸域跳转 server 不承担资源服务。
http2 on;
gzip on;
gzip_vary on;
gzip_proxied any;
gzip_min_length 1024;
gzip_comp_level 5;
gzip_types text/css application/javascript application/json
           image/svg+xml text/plain application/xml text/xml;
```

当前 edge 镜像为 Nginx 1.27 系列，实施时先检查运行版本与模块；HTTP/2 只需配置公网 TLS 连接，容器内部 HTTP/1.1 不影响浏览器协商。压缩协商必须实测 `Content-Encoding`、`Vary: Accept-Encoding` 和体积；Vite 的 minify 与 HTTP 传输 gzip 是不同环节。JPEG/WebP/WOFF2 不重复 gzip；Brotli 只作可选增强，不引入模块成为首批依赖。

保留 `/assets/` 内容哈希的一年 immutable；HTML/noindex 错误页不长期缓存。`/redesign/assets/` 当前是未带哈希的固定地址，不能直接照搬一年 immutable，推荐随构建纳入哈希产物或采用版本路径。

### 10.2 响应式图片

修改 demo `home/card/eventShell/mapReport` 与 API 首页、目录、赛事壳、比赛地图图片，不改冻结原图。新增构建前图片派生步骤，优先 WebP，保留 JPEG fallback；输出宽度初步选择 384/640/768/1024/1440/1920，并用实际容器和 DPR 验证 `sizes/srcset`。

首页图是绝对定位背景裁切。报告中手机显示约 351×535，却使用 16:9 原图，直接缩小原图宽度可能因 `object-fit:cover` 放大而模糊。手机应生成独立竖向裁切素材，例如 384×576、640×960，保留主要人物与桌面一致的视觉焦点，通过 `<picture><source media=...>` 做艺术方向切换；桌面使用横图宽度候选。目标 390px、DPR 1/2 时实际手机图宽不超过约 702px，清晰度与构图同时验收。

首屏 hero 不设置 lazy，可设 `fetchpriority=high`；首屏外卡片和地图图采用 lazy。设置宽高或稳定 aspect-ratio 避免位移。构建脚本必须检查输出存在，防止 HTML 引用了未提交的派生文件。

### 10.3 字体

本地 `frontend/public/redesign/assets` 存在 5 个标为 `.woff2` 的文件；其文件头均为 `00 01 00 00`，并非 WOFF2 的 `wOF2`，且 `fonts.css` 声明 `format('truetype')`。报告统计的是实际加载 4 个字重，不能直接认定仓库只有 4 个字体。

推荐先将所需字体转为真正 WOFF2，再使扩展名、文件头、`format('woff2')` 与 MIME 一致，保留 OFL 许可。核对全部页面与 Element Plus 的字体使用后，再决定是否删去 900 或其他不必要字重；正文、标题字重变化需截图复核。不要只改 `format` 字符串而不转换文件。仅预加载首屏确需的 1～2 个字重，继续 `font-display:swap`。

### 10.4 验收

同一构建、清缓存前提下保存桌面/390px 网络记录，区分编码前资源体积与实际传输字节。JS/CSS 协商 gzip 成功；TLS ALPN 协商 h2；手机 `currentSrc` 与自然尺寸符合选择目标；字体资源确为 WOFF2，无解析失败或请求重复。记录 LCP/CLS 作为新基线；报告未测 Core Web Vitals，不能声称优化后已达到某等级。

## 11. F-09：未知页面、无效资源与 HTTP 状态

### 11.1 现状

`main.ts` 将公开路径交给一个 catch-all，`Public.vue` 按路径前缀设标题；demo 的无效比赛仅返回文本，未知赛事/子路径也未严格验证。API `api.ts` 已保留 `error.status`，但 `Public.vue` 捕获后只留 message，404 与 503 都成为普通错误提示。web 的 `try_files ... /index.html` 使任意地址都回 200。

### 11.2 第一层：前端错误语义与静态未知路径

新增共享 `classifyPublicRoute()` 与统一 NotFound 视图，按精确规则识别根、目录、赛事、已知子页、战队详情、比赛、公告。demo 严格校验 edition、比赛 ID 和名单索引；拒绝多余路径段、负数、NaN 和小数索引。API 资源 404 显示“内容不存在”，5xx/网络失败保留重试，不能显示成不存在。

统一视图包含“页面不存在 · GDUF CS”标题、noindex、返回首页及适当赛事入口。成功导航立即移除临时 robots noindex，防止错误状态污染正常页。弹窗无内容时也给明确返回入口；客户端错误标题由错误类型覆盖通用 path 标题。

web 将 `/api/`、`/media/`、静态文件与 HTML 路由分开：

- 静态文件缺失返回真实 404，不能回退 index；尤其是 `.js/.css/.ico/.xml/.txt`。
- 已知页面路径才加载 SPA 壳；未知路径返回独立的 `frontend/public/404.html`，HTTP 404，带返回入口及 noindex。
- `/admin/login` 和既有后台 SPA 路径仍保留；不得拿公开赛事路由白名单阻断后台。
- API 与媒体保留原响应状态，错误 JSON 不被前台 HTML 错误页替换。

该层完成后，形如 `/matches/不存在ID` 的合法路由首次请求仍可能 200，必须作为剩余项记录。

### 11.3 第二层：合法路由下无资源的真 404（完整关闭条件）

推荐保持 SPA 架构，新增只读“页面存在性校验”，由 web 在返回 HTML 前校验，避免为此全面改 SSR。

建议新增 `backend/app/page_checks.py`，为内部检查提供接口；web 通过 `auth_request` 子请求调用。实施前核实 Nginx `http_auth_request_module` 已启用。处理规则：

1. 只对资源页 HTML 的 GET/HEAD 执行，静态资源、API、媒体及后台不走该检查；固定目录页直接放行。
2. 检查请求携带原始路径；路径先规范化且按共享路由契约识别，不接受任意可代理 URL。公开赛事/比赛/战队/公告重用现有发布、有效期、归属判断，尤其阻止“存在但未发布”的资源返回成功。
3. 内部成功返回 204；不存在/不可公开统一返回 403，用于适配 `auth_request` 只接受 2xx/401/403 的语义。**不能直接让校验子请求返回 404，否则 Nginx 会把它当校验异常。**
4. 仅在资源页 location 把此 403 转为对外的 404 静态页；子请求服务异常返回 5xx，资源页对应为 503，不能误报资源不存在。内部校验代理 location 标记 `internal`，避免外部将其作为常规入口。
5. demo 构建在 web 生成演示路由清单，直接校验固定 edition/比赛/队伍/公告 ID，不访问真实数据库。API 构建才启用上述资源存在性检查；构建模式注入 Nginx 模板与前端保持一致。
6. 校验只读、短超时，先不缓存结果，避免下架资源因过期缓存继续返回成功；日志保留请求路径与失败类型，评估额外一次数据库查询的代价。

需要变更 web 配置及 Dockerfile/模板、后端路由注册和对应测试，不需要迁移数据表。若只批准第一层，则 F-09 标记“部分完成”，不能用 noindex 或前端标题正确宣称全部关闭。

### 11.4 验收

直接 GET/HEAD 与客户端导航都测：未知路径、未知赛事、未知子页、无效比赛、跨届战队、未发布资源、未来公告、正常深链。HTTP 请求阶段不存在返回 404；API 404 保持 JSON；后端不可用返回服务错误。前端导航不会产生新的文档 HTTP 状态，但必须正确渲染 NotFound、title 和 noindex。

## 12. F-10：信息字号过小

修改 `reference.css` 的原始规则及媒体查询，不全站粗暴使用 `small{font-size:12px}`，因为它也包含装饰标签。

推荐增加字号变量 `--font-info:12px`、`--font-info-min:11px`，时间、状态、日期、BO/分组、比赛说明、地图标签使用 12px，紧凑辅助信息最低 11px。检查 `font` 简写以及更靠后的 380px、品牌细化规则，避免只改 `font-size` 后又被覆盖。

逐项覆盖报告中的 `.event-card-info .status`、`.fixture-time small`、`.match-final small`、`.map-tab small`、`.schedule-note`、`.ribbon-date`。`.brand small` 当前是 `aria-hidden` 留白占位，不是可读信息，不因为报告列了选择器而填回已移除的中文。首页学校英文品牌字属于装饰例外，可保留小字号，但不得承载日期、状态等唯一信息。

增大字号后依靠换行、内边距和 F-02/F-06 的布局调整容纳，不缩回字号或隐藏状态。验收取计算样式而非只扫源代码；360/390px、200% 文本放大、长队名与长直播按钮均不丢信息。真机及微信浏览器可读性需后续实测，不以像素下限代替无障碍合规结论。

## 13. F-11：安全响应头缺失与继承

### 13.1 明确职责

建议由 edge 统一输出面向浏览器的安全头，web 管理资源缓存；避免两层发送不同 CSP。对 edge 上任何声明其他 `add_header` 的 location 都显式 include 同一安全头片段，解决继承问题。web 的独立本机/CI 入口也配置同等非 TLS 安全头片段，避免只测 8080 就误认为公网配置正确。

新增配置片段建议：`deploy/snippets/security-headers.conf`，通过 Compose 挂载至独立 snippets 目录并显式 include，不能放到会被 `conf.d/*.conf` 自动作为 server 配置加载的位置。相应调整 `deploy/compose.ip.yaml` 与 web 镜像所需配置复制。最终以 `nginx -T` 展开的配置为准。

### 13.2 策略

- HTTPS edge：HSTS 初期 `max-age=86400`；裸域/www、续期和回滚验证稳定后升至 `31536000`。本次不默认添加 includeSubDomains 或 preload。
- 全部正常及错误响应：`X-Content-Type-Options:nosniff`、`Referrer-Policy:strict-origin-when-cross-origin`；用强制 CSP 的 `frame-ancestors 'none'` 或 `X-Frame-Options:DENY` 禁止被第三方嵌入。CSP Report-Only 不负责实际阻断 iframe，应保留明确强制措施。
- 基础 CSP 从现有资源来源出发：default/script/connect/font 自站，img 自站及 data，style 允许现有 inline，base-uri 自站，object-src none。先在隔离环境用 Report-Only 观察，再验证生产只读路径并转强制。
- 当前 web 有强制 CSP；迁移观察策略时需同步调整旧头，不能同时存在一条更严格的旧 CSP 造成“Report-Only 不生效”的错觉。媒体、字体和 Element Plus 样式重点验证。
- 若没有 CSP 报告接收端，明确采用浏览器控制台及测试监听 `securitypolicyviolation` 收集证据，不把“已配置 Report-Only”当作已建立线上报告系统。

### 13.3 验收

分别检查首页 HTML、深链、JS、CSS、字体、图片、API 成功/失败、404、301 的响应头，含 `always`；检查重复头及相互冲突。验证后台登录、CSRF、弹窗、直播外链和样式不受影响。保持 `PUBLIC_ORIGIN`、Cookie 和同源校验逻辑不变。

## 14. F-12：favicon、爬虫与分享元信息

### 14.1 静态文件

在 `frontend/public/` 新增真实 favicon（可包含 SVG 与 ICO）、`robots.txt`、`sitemap.xml`，使用固定 www 正式地址。图标沿用当前 G/ 品牌，不引入新品牌设计。静态文件规则返回正确 MIME；不存在文件返回 404，不能返回首页 HTML。

robots 建议允许公开内容，禁止抓取 `/admin/` 与 `/api/`，并声明 sitemap；robots 不是访问权限控制。sitemap 仅列规范、可公开、可访问的地址，不收录后台、API、筛选参数或 404。

demo 构建可生成固定公开演示路由清单，分享说明明确“示例赛事”。API 模式最低先列稳定目录页；如果要收录动态赛事与比赛，后续由后端按发布状态生成 XML，经 web 的精确 `/sitemap.xml` location 代理并短缓存，不能把所有数据库 ID 直接导出，也不增加数据库迁移。

### 14.2 页面 head 与分享

`frontend/index.html` 加基础 description、OG title/description/image、canonical、favicon；OG 图片与 canonical 使用绝对 HTTPS www URL。新增 `updatePageMeta()` 与 F-09 的状态渲染统一：正常导航更新 title/description/canonical，错误页设置 noindex 并避免遗留上一页描述。筛选 query 通常归一到不带筛选参数的页面 canonical。

客户端更新 OG 不保证微信、QQ 或其他不执行 JS 的抓取器读到动态值。本轮基础交付应保证原始 HTML 具有站点级分享信息；若要求每场比赛各自生成分享卡片，需增加服务端 head 注入/预渲染或 SSR，属于单独扩展，不把它包装为前端加标签即可完成。OG 图片使用可公开静态品牌素材，不含虚构真实参赛者信息。

验收：直接获取 HTML 已有基础标签且无重复；favicon 可显示；robots 为 text/plain、sitemap 为 XML；微信/QQ 分享结果需实际验证，不能从 meta 存在就判通过。

## 15. 报告第 6 节：字符串渲染风险的处理

此项单列，不将其描述为已经确认的 XSS 漏洞。API 模式 `data.ts` 已有 `escape()` 并广泛用于动态文本、公告及属性；演示模式模板则含大量直接插值。`Public.vue` 主内容与弹窗均使用 `v-html`，必须持续审核每个数据入口。

推荐分两步：

1. 近期复用公共转义与 URL 校验函数，审查新增字段是文本、属性还是 URL 上下文；URL 先协议/来源校验再属性转义。不在 API 原始数据层统一预先转义，防止重复转义及污染非 HTML 逻辑。demo 数据始终保持隔离。
2. 后续按赛程行、比分、积分榜、战队和公告逐个迁移 Vue 模板组件，优先处理可编辑字段；不为修 F-01 强行同步重构全部页面。HTML 模板确有必要时保留有边界的静态片段。

已有 `api-mode.spec.ts` 覆盖公告恶意 HTML 被显示为文字；新增队名、昵称、赛事名、图片 alt 和链接属性样例：`<img src=x onerror=alert(1)>`、引号、`&`、相似 B 站域名、非 HTTPS。只在隔离 mock/验收环境使用这些字符串，不向生产提交测试内容。

1. 裸域精确 301 与完整 Location（不能仅 curl 退出成功）。
2. JS/CSS Content-Encoding 包含实际支持编码，记录传输量。
