# 交付、验收与待确认事项

版本：V1.2｜2026-11-08

## 1. 实施顺序与最终验收

开发遵循索引最前面的开发原则：专注于功能实现，不进行防御性编程。阶段 1～7 集中完成功能，不穿插代码审查、测试编写或测试执行；下表功能产物及后续全部验收项统一在阶段 8 检查。

| 阶段 | 内容 | 功能实现产物（统一在最后环节验收） |
| --- | --- | --- |
| 1 | 工程、数据库迁移、唯一管理员、同域 API、设计样式隔离 | 页面可读真实数据库；游客写操作被拒绝；管理员可登录退出 |
| 2 | 选定首页静态复现 | 按原稿完成结构、样式、断点和本地交互，保留相同示意数据用于最终对照 |
| 3 | 赛事、名单、Excel 导入与战队公开页 | 一份 16 队文件成功整批导入，公开字段正确；错误文件零写入 |
| 4 | 三种模板、种子与分组、赛程预览发布 | 实现 16／32 队及非二次幂对阵生成，支持轮空和显式晋级来源 |
| 5 | 地图、BO、确认、积分晋级与受控修正 | 真实 API 打通一届赛事，重复请求与结果修正不重复加分、不破坏下游 |
| 6 | 公告、直播、历史、其他前台页面 | 所有游客路径免登录；管理操作可独立完成；全部入口有实际功能 |
| 7 | 生产配置、备份恢复脚本与部署说明 | 完成部署配置、备份恢复工具及交付说明 |
| 8 | 统一代码审查与测试 | 集中审查代码，编写并执行单元、集成、端到端、压力及视觉测试，完成备份恢复验证；统一修复问题并复测，通过最终验收后交付 |

以上是工程顺序，不是用户新增的分期交付承诺；第一版最终仍需完整闭环。具体工期在实际开发和资源确定后估算，不根据文档篇幅承诺固定完成日期。

## 2. 核心验收用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 游客访问赛事、赛程、战队、比分、公告、直播页 | 无需登录；不显示公开报名、注册、个人中心 |
| A02 | 游客直接请求全部管理写接口 | 401／403，数据库无变更；不是只靠隐藏按钮 |

| A06 | Excel 一队只有四正式或超替补上限 | 定位到队伍／行列，整批不导入 |

| A14 | 20／24／28 队小组＋单败 | 小组赛完整，晋级 10／12／14 队按配置处理轮空，无虚假比分 |
| A15 | 双败标准模板及总决赛 | 胜败者去向正确；重置规则按已确认配置，冠军路径可完整模拟 |
| A16 | BO1／BO3／BO5 正常成绩及非法地图数量 | 所需胜场正确；未满足终局或超额有效地图拒绝确认 |
| A17 | 弃权、技术判负、延期、取消 | 状态与结果类型明确；统计遵循赛事配置，不伪造地图回合数 |
| A18 | 三队循环互胜、多重同分 | 执行已配置细则；无法确定时待裁定，不按 ID 自动晋级 |
| A19 | 已确认结果重试／修正，下游尚未开始 | 不重复累加；旧晋级撤销、新晋级正确、原因和版本留存 |
| A20 | 修正影响已开始／已结束下游比赛 | 阻止静默提交，返回具体阻塞比赛 |
| A21 | 赛程发布后再次生成／重复发布 | 不覆盖历史，不重复创建；必须显式处理旧草稿 |
| A22 | B站嵌入不可用或无直播配置 | 外链可用；无配置不展示假直播 |
| A23 | 草稿赛事、未到发布时间公告、私密日志 | 对游客不可见，不通过猜 URL 绕过 |

以下测试统一在最终环节编写和执行：赛制算法、导入事务、结果修正用自动化单元／集成测试；关键完整流程用端到端测试。验收测试使用独立数据库，不使用生产数据。不要为每个 CSS 值写镜像测试；首页采用实际浏览器视觉比较。

## 3. 视觉与交互验收

- 基准：`前端设计基准/广金主场_观赛优先_选定稿.fragment.html`；具体方式见 `04`。
- 固定示例内容和同一字体环境，在 1024／760／540／390／320px、浅深主题分别检查。
- 顶部院校条、红线、主品牌、四栏目、两栏主视觉、GDUF 字形、木棉纹样、校训、焦点比分、地图与积分、日期、赛程、页脚逐项对照。
- 日期和赛果切换、滚动定位、触屏点击、键盘焦点与真实路由全部可用。
- 长队名、无 Logo、无比赛、取消／延期、网络失败不溢出；不在移动端隐藏核心积分信息。
- 禁止以“电竞风格相近”代替还原验收；必要设计变更必须列出差异并经用户认可。

## 4. 性能与运行验收

按原 PRD，100 个并发访问用户持续至少 10 分钟，包含首页、赛事、战队、赛程与比赛详情的真实读取比例。P95 普通公开 API ≤2 秒，5xx 错误率 <1%，无 OOM 或数据库异常退出。并发用户不等于固定 100 请求每秒；压测报告写清思考时间、请求频率和环境。

记录 CPU、内存、数据库连接数、慢查询、磁盘与带宽。先优化资源体积、SQL 和缓存，再根据证据决定是否升级 2核4GB。不能把 2核2GB 的候选配置写成已验证承载保证。

生产检查：HTTPS、唯一管理员改密、Cookie／CSRF／限流、上传校验、私密接口、数据库不对公网开放、环境变量不进仓库、日志轮转、时区一致、容器重启、健康检查、备份失败告警。

## 5. 备份、恢复与部署交付

必须交付前后端源代码、依赖锁文件、Alembic 迁移、模板生成逻辑、Dockerfile／Compose、Nginx、`.env.example`、初始化管理员命令、备份恢复脚本、完整中文部署说明和测试报告。

数据库每日备份建议保留 7 份，并在名单锁定、赛程发布、淘汰赛开始等关键节点额外备份；实际保留周期按可用磁盘确定。至少一份备份在服务器之外，包含图片资源对应备份。上线前必须在空数据库实际恢复并验证队伍、比赛、晋级和图片，不能只确认文件生成成功。

升级前备份，迁移由单次部署任务执行；失败停止发布，旧镜像与配置可回退。不可假设回滚应用镜像能自动撤销不兼容数据库迁移。

部署仍按原 PRD 的自托管 Vue 静态前端＋FastAPI＋PostgreSQL 设计。本次保存的预览不是生产平台，也没有产生公网部署。域名、校方资源、主机费用和国内上线条件在采购／上线前按实际资源核验；原 PRD 截图报价和额度仅为历史记录。

## 6. 待确认事项及处理边界

| 事项 | 当前状态／建议 | 何时必须明确 |
| --- | --- | --- |
| Excel 现有格式 | 双工作表为实施默认；现有表格尚未提供／确认 | 冻结模板、编写正式适配前 |
| 首届实际赛制 | 未选定；三种模板交付范围不变 | 首届赛事创建发布前 |
| 分组与种子 | 支持随机／手动／混合；实际方法未定 | 发布抽签及对阵前 |
| 小组单／双循环、晋级数、季军赛 | 可配置，首届值未定 | 生成赛程前 |
| 三队及以上同分 | 需确定小积分表及递归重算细则 | 发布赛事规则前 |
| 跨组种子与非二次幂轮空 | 需确定比较与分配口径 | 相应模板发布前 |
| 双败总决赛重置 | 未定，需明确是否重置或其他优势规则 | 双败模板用于正式赛事前 |
| 地图池、加时、合法比分及异常统计 | 需赛事规则明确，不硬编码示意地图为当前官方地图池 | 正式录分前 |
| 队长必须正式成员 | 本文建议与导入默认；用户未逐项确认 | 冻结参赛名单规则前 |
| 队伍、赛事、组织方正式名称 | 页面文案示意，不能作为主办事实 | 正式发布内容前 |
| 正式校徽、Logo、图片素材 | 原稿仅有抽象木棉与字形；正式校徽另用正确原图 | 增加相应素材前 |
| B站直播间与嵌入 | 未提供具体房间，也未验证实际嵌入 | 上线直播模块前 |
| 导入原文件保留期限 | 建议短期，审计结果长期保留至项目归档 | 生产数据收集前 |
| 学校域名、服务器与预算 | 尚未核实；不把历史试用截图当现价 | 公网部署／采购前 |

以上不需要阻止独立模块开发，但涉及未定比赛规则时不能默默选择后宣称用户已确认。开发文档版本发生变更需在索引中记录，并保持原设计快照不变。

## 7. 本次文档包核验与后续验收的区分

本次可以核验：文件完整、链接存在、设计快照哈希一致、选定区块准确提取、CSS／脚本未改、导出预览生成成功。

本次尚不能核验：产品业务测试、生产页面像素比较、B站实际播放、服务器并发和备份恢复。它们属于未来开发交付门槛，不得写成已通过。
