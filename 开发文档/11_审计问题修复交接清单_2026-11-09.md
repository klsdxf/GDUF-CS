## 6. 接手执行顺序

1. **核对交付版本（开发者）**：从发布分支取得源码，与外置 `release-manifest.json` 核对 SHA 和源码包哈希；确认目标 `VITE_PUBLIC_DATA_MODE`。本轮不擅自切换生产模式。
2. **完成部署前验证（开发者/维护者）**：启动隔离 Docker 环境，验证 demo 与 API 构建的 Nginx 路由、安全头、真实 404/503；补跑独立数据库 E2E。F-09 API 模式依赖新后端接口，须先部署兼容后端。
3. **准备域名链路（维护者）**：核实 DNS、实际服务器和现用证书/续期；完成裸域与双域名 SAN，不直接采用旧文档的 IP 快照。
4. **保存恢复点并发布（维护者）**：保存旧提交、镜像 digest、构建模式、nginx -T、配置和证书恢复点，按现有项目交接流程发布。源码模板变更后须确认实际生成的 `storage/ip-edge/domain.conf` 已更新。
5. **执行上线核验（维护者/验收者）**：运行只读 `bash scripts/audit-smoke.sh`；补验 API 模式缺资源和服务异常，检查管理登录、只读查询、媒体及深链；完成两种模式相应页面复现。
6. **补齐专项验收并关闭（验收者）**：按第 2～4 节完成边界/真机/分享检查。每项保存提交、模式、环境、时间、截图或 HTTP 原始输出，再登记“线上已关闭”。

回退沿用主交接文档：保留旧镜像/配置，先 `nginx -t` 再 reload，不删除持久卷；F-09 校验回退后应重新标记为部分完成。证书私钥、真实 `.env`、凭据不进入证据目录或 Git。
